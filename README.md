# H₂O₂ 분해 속도 예측 프로그램

과산화수소(H₂O₂)의 촉매 분해 실험에서 **온도·촉매 질량·초기 농도**가 **산소 발생 속도**에 미치는 영향을 다중선형회귀로 분석하는 C++ CLI 프로그램입니다.

실험 계획 수립부터 데이터 입력, 회귀 분석, 조건 예측, 최적 조건 탐색, MATLAB 시각화까지 한 흐름으로 이어집니다.

**외부 라이브러리를 쓰지 않습니다.** 최소제곱법도 가우스 소거법도 직접 구현했습니다.

---

## 1. 변인

| 구분 | 변인 | 기호 | 단위 |
|---|---|---|---|
| 입력 | 온도 | T | °C |
| 입력 | 촉매 질량 | C | g |
| 입력 | H₂O₂ 초기 농도 | H | M |
| **출력** | **산소 발생 속도** | v | **mL/s** |

구하려는 모형:

```
v = β₀ + β₁·T + β₂·C + β₃·H
```

---

## 2. 빌드와 실행

### 필요한 것
- C++20을 지원하는 컴파일러 (개발 환경: g++ 16.1.0, MinGW-W64)
- 시각화용 MATLAB (선택 — 프로그램 자체는 없어도 동작)

### 빌드

```powershell
g++ -std=c++20 -Wall main.cpp model.cpp storage.cpp ui.cpp linalg.cpp regression.cpp optimizer.cpp -o co2.exe
```

빠르게 돌리려면 `-O2` 를 추가하세요. 격자 탐색이 2~4배 빨라집니다.

### 실행

```powershell
.\co2.exe
```

첫 실행 시 `data/` 와 `output/` 폴더가 자동으로 만들어집니다.

> **한글이 깨진다면** 콘솔 글꼴을 `D2Coding`, `NanumGothicCoding` 등 한글을 포함한 고정폭 글꼴로 바꾸세요. 프로그램은 시작할 때 코드 페이지를 UTF-8로 바꾸지만, 글꼴에 글자가 없으면 표시되지 않습니다.

### [6] 실험 가이드 — 여기서 시작하세요

각 변인의 최소·최대만 넣으면 4수준으로 나눠 **16회짜리 실험 계획표**를 만들어 줍니다. 표를 CSV로 저장하면 `o2_rate_mL_s` 열이 `0` 으로 비어 있는데, 실험하면서 그 칸만 채워 넣고 `[1]` 로 다시 불러오면 됩니다.

4수준 3변인을 전부 하면 64회지만, 라틴방격 설계로 **16회만 해도 각 변인의 효과를 분리해 낼 수 있습니다.** (자세한 내용은 [5-5](#5-5-라틴방격-실험-설계))

### [1] 실험 데이터 입력

- **직접 입력** — 값 4개를 반복해서 넣고 파일명을 지정해 저장
- **CSV 불러오기** — `data/` 폴더의 파일 목록에서 번호로 선택

숫자가 아닌 값을 넣으면 다시 물어보고, 잘못된 CSV는 **몇 번째 줄이 문제인지** 알려줍니다.

### [2] 저장된 데이터 조회

표와 변인별 최소·최대 요약을 보여줍니다. 여기서 **잘못 입력한 행을 삭제**하거나 전체를 초기화할 수 있습니다.

### [3] 회귀 모델 생성

계수 β₀~β₃, R², RMSE, 그리고 **변인 영향도**를 계산합니다.

데이터가 부족하거나(4건 미만), 변인 하나를 고정한 채 실험했거나, 측정값이 전부 같으면 각각에 맞는 안내가 나옵니다.

### [4] 산소 발생 속도 예측

조건 3개를 넣으면 예측값을 돌려줍니다. **실험 범위를 벗어난 값을 넣으면 경고**가 뜹니다 — 계산은 되지만 근거가 없는 값이기 때문입니다.

### [5] 최적 반응 조건 탐색

탐색 범위를 잘게 나눠 모든 조합의 예측값을 계산하고 상위 5개를 보여줍니다. 세 가지 기준 중에서 고를 수 있습니다.

| 모드 | 찾는 것 |
|---|---|
| 1 | 반응 속도가 가장 빠른 조건 |
| 2 | 목표 속도에 가장 가까운 조건 |
| 3 | 목표 속도를 내면서 **촉매를 가장 적게 쓰는** 조건 |

> 모드 1은 계수가 모두 양수면 답이 항상 탐색 범위의 구석에 나옵니다. **실용적으로는 모드 2·3이 더 유용합니다** — 서로 다른 조합이 같은 속도를 내기 때문에 실험 여건에 맞는 것을 고를 수 있습니다.

MATLAB에 넘길 파일을 만듭니다. 파일명(예: `result_260910`)을 입력하면 `output/` 에 접미사가 붙어 저장됩니다.

## 5. 수학적 배경

### 5-1. 최소제곱법과 정규방정식

실험이 n건이면 식이 n개, 미지수는 4개(β₀~β₃)입니다. n > 4 이면 **모든 식을 동시에 만족하는 답은 없습니다** — 측정 오차가 있으니까요.

그래서 오차 제곱의 합이 최소가 되는 β를 찾습니다.

```
S = Σ (실측ᵢ - 예측ᵢ)²   →   최소
```

S를 각 β로 편미분해서 0으로 놓고 정리하면 **미지수 4개, 식 4개**의 연립방정식이 나옵니다.

```
(XᵀX) β = Xᵀy
```

- `X` : 각 행이 `[1, T, C, H]` 인 n×4 행렬 (맨 앞 1은 절편용)
- `y` : 측정한 속도 n개

즉 **n개짜리 문제가 4×4로 압축**됩니다. `XᵀX` 의 원소는 사실 Σx, Σx², Σxy 같은 요약 통계량 덩어리입니다.

| 함수 | 역할 |
|---|---|
| `xt_x()` | 연립방정식의 **좌변(계수)** 을 만든다 |
| `xt_y()` | **우변** 을 만든다 |
| `solve()` | 그 연립방정식을 **푼다** |

### 5-2. 계수 크기로 영향력을 비교하면 안 되는 이유

회귀 결과가 이렇게 나왔다고 합시다.

```
β₁ (온도)  = 0.0156
β₂ (촉매)  = 2.9501     ← 200배 가까이 크다
β₃ (농도)  = 1.5688
```

계수만 보면 "촉매가 압도적이고 온도는 무의미하다"로 읽힙니다. **하지만 틀렸습니다.** 단위가 다르기 때문입니다. 온도를 1 °C 올리는 것과 촉매를 1 g 늘리는 것은 애초에 크기가 다른 사건입니다.

실험에서 각 변인이 **실제로 움직인 폭**을 곱해야 공정합니다.

```
영향도 = |β| × (실험 최댓값 - 최솟값)

온도 : 0.0156 × 20.0  = 0.313 mL/s
촉매 : 2.9501 × 0.25  = 0.738 mL/s
농도 : 1.5688 × 0.50  = 0.784 mL/s   ← 실제로는 농도가 1위
```

**순위가 뒤집힙니다.** `[3]` 메뉴와 Figure 3이 이 두 가지를 나란히 보여줍니다.

### 5-3. 가우스 소거법

4×4 연립방정식을 푸는 방법입니다. 중학교 가감법을 컴퓨터가 따라 할 수 있게 순서를 정한 것입니다.

1. **전진 소거** — 아래 행에서 변수를 하나씩 없애 계단(위삼각) 모양을 만든다
2. **후진 대입** — 맨 아래 행부터 거꾸로 올라오며 값을 구한다

**부분 피벗팅**을 함께 씁니다. 각 단계에서 그 열의 절댓값이 가장 큰 행을 위로 올리는 것인데, 소거할 때 그 값으로 나누기 때문입니다. 작은 수가 분모가 되면 소수 계산 오차가 크게 증폭됩니다.

### 5-4. 언제 회귀가 실패하는가

`XᵀX` 가 특이행렬이면 해가 없습니다. 실험 설계가 잘못된 경우입니다.

- **변인 하나를 고정한 경우** — 농도를 전부 0.5 M로만 실험했다면, 농도의 효과를 계산할 근거가 아예 없습니다.
- **두 변인이 항상 함께 움직인 경우** — 온도를 올릴 때마다 촉매도 같이 늘렸다면, 속도 변화가 무엇 때문인지 구분할 수 없습니다.

`[6]` 의 라틴방격 설계는 정확히 이걸 피하기 위한 것입니다.

### 5-5. 라틴방격 실험 설계

4수준 3변인을 전부 실험하면 4³ = 64회입니다. 온도(i) × 촉매(j)를 완전 조합(16칸)으로 두고, 농도를 `(i + j) mod 4` 로 배정하면 **16회로 줄일 수 있습니다.**

```
        촉매0  촉매1  촉매2  촉매3
온도0 │  농도0  농도1  농도2  농도3
온도1 │  농도1  농도2  농도3  농도0
온도2 │  농도2  농도3  농도0  농도1
온도3 │  농도3  농도0  농도1  농도2
```

각 행과 각 열에 농도 0~3이 정확히 한 번씩 나옵니다(스도쿠와 같은 원리). 그 결과 **세 변인 중 어느 두 개를 짝지어 봐도 모든 조합이 정확히 한 번씩** 나타나서, 변인들이 서로 겹쳐 움직이지 않습니다.

실험량은 1/4이지만 각 변인의 1차 효과는 그대로 추정됩니다. 잃는 것은 변인 간 상호작용인데, 우리 모형에는 그런 항이 없으므로 손해가 없습니다.

## 6. 코드 구조

```
main.cpp            메뉴 화면과 프로그램 흐름
├── ui.h/.cpp       화면 출력, 사용자 입력  (model 을 모름)
├── storage.h/.cpp  CSV 입출력
├── model.h/.cpp    Record, DataSet
├── regression.h/.cpp  최소제곱법, R², RMSE
│   └── linalg.h/.cpp  XᵀX, Xᵀy, 가우스 소거법  (아무것도 모름)
└── optimizer.h/.cpp   격자 탐색
```

의존 방향은 **아래(범용) → 위(전용)** 한 방향입니다. `linalg` 는 실험 데이터가 뭔지 모르고, `ui` 는 `Record` 가 뭔지 모릅니다. 덕분에 두 모듈은 다른 프로그램에 그대로 가져다 쓸 수 있고, 단위 테스트도 따로 할 수 있습니다.

| 파일 | 핵심 |
|---|---|
| `model` | `Record`(실험 1회), `DataSet`, `Range`, `Column` enum |
| `storage` | `save_csv`, `load_csv`, `write_csv`, `list_csv_files` |
| `ui` | `display_width`, `pad`, `print_table_*`, `read_double`, `to_fixed` |
| `linalg` | `xt_x`, `xt_y`, `solve` |
| `regression` | `Model`, `fit`, `Model::predict` |
| `optimizer` | `Candidate`, `grid_search` |

### 알아둘 만한 구현 사항

**한글 표 정렬** — `std::setw` 는 **바이트 수**로 셉니다. UTF-8에서 한글 한 글자는 3바이트인데 화면에서는 2칸을 차지하므로 표가 어긋납니다. `display_width()` 가 UTF-8 코드포인트를 계산해 한글(2칸)과 박스 문자(1칸)를 구분합니다.

> 이 때문에 **소스 코드의 표·박스 정렬을 편집기에서 눈으로 맞추면 안 됩니다.** 편집기와 콘솔이 한글 폭을 다르게 그리기 때문에 둘 중 하나는 반드시 어긋납니다.

**인덱스 규칙** — 사용자에게 보이는 행 번호는 1-기반(`get_record(1)` 이 첫 행), 내부 벡터는 0-기반입니다. `model.fitted[i-1]` 처럼 변환하는 자리가 여러 곳 있습니다.

**예외 설계** — 사용자가 고칠 수 있는 문제는 전용 타입, 프로그래머의 실수는 표준 예외로 나눴습니다.

| 예외 | 뜻 | 누가 고치나 |
|---|---|---|
| `NotEnoughData` | 데이터가 4건 미만 | 사용자 (실험 추가) |
| `SingularMatrix` | 변인이 고정됐거나 겹침 | 사용자 (실험 재설계) |
| `ConstantResponse` | 측정값이 전부 같음 | 사용자 (측정 확인) |
| `InputCancelled` | 입력이 끊김 (EOF) | — |
| `std::invalid_argument` | 배열 크기 불일치 등 | 개발자 (코드 버그) |

던지는 곳은 하위 모듈, 잡는 곳은 메뉴 층입니다. 그래야 원인별로 다른 안내를 할 수 있습니다.

## 7. 데이터 형식

```csv
temperature_C,catalyst_g,h2o2_M,o2_rate_mL_s
20,0.10,0.50,1.980
30,0.10,0.50,2.130
```

헤더는 있어도 없어도 읽힙니다. 첫 줄의 첫 칸이 숫자로 변환되지 않으면 헤더로 판단합니다.

## 8. 한계

- **선형 근사** — 실제 반응 속도는 온도에 대해 아레니우스 식(지수)을 따르고, 촉매는 일정량 이상에서 포화됩니다. 직선 근사가 유효한 것은 **좁은 실험 범위 안에서**입니다. 범위를 넓게 잡으면 R²가 떨어지고 Figure 4의 잔차가 휘어집니다.
- **외삽 불가** — 실험하지 않은 구간의 예측은 수식상 계산될 뿐 근거가 없습니다. `[4]`, `[5]` 가 경고를 띄우지만 막지는 않습니다.
- **상호작용 항 없음** — "온도가 높을 때는 촉매 효과가 더 크다" 같은 관계는 이 모형이 표현하지 못합니다.
- **탐색 정밀도** — 격자 간격을 모델 오차(RMSE)보다 훨씬 작게 잡는 것은 의미가 없습니다. 모델이 구분하지 못하는 차이를 계산하는 셈이기 때문입니다.
